## 1. 背景与目标

用户需要在资源管理器中右键选择 Markdown 等文件，用 pongrabbit-MD 打开；**不同文件应出现在各自独立的应用窗口中**，便于多文档对照编辑。

当前实现为单窗口 + 单实例锁：第二次打开文件会把路径发给已有窗口并切换当前文档，不符合预期。

**产品目标**：

- 支持单进程多 `BrowserWindow`，每个窗口独立编辑一份文档。
- 保留 `requestSingleInstanceLock()`，避免每次右键启动完整新进程。
- 全局配置（主题、字体、工作区、最近文件等）仍共享；文档内容与未保存状态按窗口隔离。

---

## 2. 产品规则（已确认）

| # | 场景 | 行为 |
|---|------|------|
| R1 | 资源管理器 / 命令行 / 双击关联文件打开 | 若该文件已在某窗口打开 → **聚焦该窗口**；否则 **新建窗口** 并打开文件 |
| R2 | 菜单/快捷键「新建」(Ctrl+N) | 先处理未保存更改；再询问 **「新窗口」/「当前窗口」/「取消」** |
| R3 | 关闭最后一个窗口 | **不变**：Windows 退出应用；macOS 保持现有 `window-all-closed` 逻辑 |
| R4 | 菜单「打开…」、工作区、最近文件 | 在当前窗口打开；若目标文件已在其他窗口打开 → **聚焦该窗口**（与 R1 一致） |
| R5 | 同一时刻多个「无题文档」 | 允许，不做去重 |

## 3. 技术方案

### 3.1 架构

```
资源管理器右键打开
        │
        ▼
  第二进程启动（带文件路径 argv）
        │
        ▼
 requestSingleInstanceLock → 第二进程退出
        │
        ▼
 首进程 second-instance(argv)
        │
        ├── 文件已打开 → focusWindow(existing)
        └── 否则 → createWindow(filePath)
```

- **单进程多窗口**：内存与配置共享，符合 VS Code / Typora 类桌面编辑器习惯。
- **主进程维护** `filePath → BrowserWindow` 映射；渲染进程在文档路径变化时通过 IPC 上报。
- **IPC 改造**：对话框、窗口控制、导出等由原全局 `mainWindow` 改为 `BrowserWindow.fromWebContents(event.sender)` 或 `getFocusedWindow()`。

### 3.2 配置归属

| 类型 | 存储 | 说明 |
|------|------|------|
| 全局 | `config.json` | 主题、字体、工作区、音乐、最近文件、`windowBounds`（作新窗口默认尺寸） |
| 每窗口 | 渲染进程内存 | 文档内容、`currentFile`、未保存标记、只读状态 |
| 每窗口 | 主进程 `windowStates` | 初始打开路径、Windows 自定义最大化状态 |

新窗口位置：相对上一窗口偏移约 28px，避免完全重叠。

### 3.3 平台差异

| 平台 | 文件传入方式 |
|------|----------------|
| Windows | `process.argv` / `second-instance` 的 `argv` |
| macOS | `open-file` 事件 + `argv` |

`package.json` 中已有 `.md` / `.markdown` 文件关联，无需改安装器配置。

## 4. 交互说明

### 4.1 外部打开文件

1. 用户右键 `.md` → 用 pongrabbit-MD 打开。
2. 应用已运行：新文件 → 新窗口；已打开文件 → 前置已有窗口。
3. 应用未运行：启动并单窗口打开该文件。

### 4.2 新建文档（Ctrl+N / 文件 → 新建）

1. 若当前文档有未保存修改 → 现有三选一：「保存」「不保存」「取消」。
2. 若选择保存 → 先执行保存，再继续。
3. 弹出：「是否在新窗口中打开空白文档？」→ **新窗口** / **当前窗口** / **取消**。
4. **新窗口**：主进程 `createWindow()`，当前窗口内容不变。
5. **当前窗口**：清空编辑器，标题为「无题文档」。

### 4.3 窗口标题

- 有文件：显示文件名（与现有一致）。
- 无文件：「无题文档」。

## 5. 范围

### 5.1 In Scope

- 多窗口创建、关闭、聚焦与文件去重
- IPC 窗口感知改造
- 新建文档窗口选择对话框
- Windows / macOS 外部打开文件
- 重新打包安装包供验收

### 5.2 Out of Scope

- 窗口间拖拽合并、分屏
- 每窗口独立主题/字体
- Tab 多文档单窗口模式
- 任务栏分组策略变更

## 6. 验收标准

| ID | 用例 | 预期 |
|----|------|------|
| T1 | 应用已开，右键打开 `A.md` | 新窗口显示 A |
| T2 | 再右键打开 `B.md` | 再出现一个窗口显示 B |
| T3 | 再右键打开 `A.md` | 不新建窗口，聚焦已开 A 的窗口 |
| T4 | Ctrl+N → 选「新窗口」 | 新空白窗口；原窗口文档不变 |
| T5 | Ctrl+N → 选「当前窗口」 | 当前窗口变为空白无题文档 |
| T6 | 关闭全部窗口 (Windows) | 应用退出 |
| T7 | 菜单打开、工作区打开已占用文件 | 聚焦已有窗口 |
| T8 | 各窗口独立编辑、保存 | 互不影响 |

---

## 7. 风险与备注

- **config.json 并发写**：单进程多窗口无多进程竞争；`pendingContent` 全局恢复与多窗口冲突，本版不在多窗口间共享未命名草稿。
- **最大化状态**：Windows 无边框自定义最大化改为每窗口独立状态。
- **主题切换**：全局主题变更时同步应用到所有窗口的毛玻璃/背景材质。
